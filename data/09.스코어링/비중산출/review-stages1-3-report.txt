대구 공실 스코어링 — 1~3단계 재검토 결과와 해결 권고
기준일: 2026-11-19
범위: 기존 단계의 재검토. 4단계 추천 순위·부트스트랩 분석은 진행하지 않았다.
기존 엔진·설정·단계별 보고서·결과는 변경하지 않았다. 이번 문서는 수정 적용 내역이 아니라 검증 결과와 수정 권고다.

종합 판정
현재 3단계 후보는 재현 가능한 통계적 비중으로 보존할 수 있다. 그러나 확정 가중치 또는 실제 임차인의 중요도로 승인할 근거는 아직 없다.
현재 데이터의 수치 오류는 발견하지 않았지만, 실행 도구의 예외 처리·설정 검증과 보고서의 기준 표시는 고칠 필요가 있다.
방법의 일반성과 현재 파일에 맞춘 파일럿 도구의 재사용성을 구분해야 한다. 앞서 '독립 진행 가능'이라는 설명은 방법 개발·고정 버전 실험을 뜻하며 산식 변경과 무관하게 결과가 확정된다는 뜻이 아니다.

1. 이번에 다시 확인한 증거
- 저장된 도구의 수치·예외 처리 단위 테스트 11개를 다시 실행해 통과했다.
- 3단계 계산 전체를 별도 작업 폴더에서 다시 실행했다. 재생성한 결과 JSON의 SHA-256이 기존 파일과 완전히 같았다.
  ac741a6aff171e164a42c32dfa4b90933430c21febc7524ab6efb12585f06b1f
- 재구성한 임대료 부담은 4개 예산×2,669건=10,676개를 기존 보간 연산 순서 및 동일 소수점 반올림과 대조했다. 불일치 0개였다.
- 현재 144개 조건별 결과에는 산출 불가·상수로 인한 결과 누락이 없었다. 144개는 서로 다른 실제 사용자 평가 144건이 아니라 업종·예산·정규화의 계산 레코드다.
- 기준 입력 10개 원본과 스냅샷의 해시가 일치했다.
- 별도 리뷰에서도 현재 수치의 오류는 발견하지 않았다. 아래 구현·표현 보완점은 독립적으로 지적되거나 격리 사례로 재현했다.

2. 반드시 보완할 구현·표현

F1. 산출 불가를 보고한다는 규칙과 실제 동작이 다름
위치: tools-stage3/calculate_stage3.py 172~174행.
규칙: 그룹이 전부 상수이거나 정보량이 0이면 cannot_estimate와 기존 비중 fallback을 기록한다.
현재 동작: 핵심 함수는 이 상태를 정상 반환하지만, 최종 집계에서 candidateWeights가 None이면 전체 실행을 ValueError로 중단한다. 출력 파일을 만드는 단계까지 가지 못한다.
재현: 식음료 공간 그룹의 인자들을 모두 50으로 만든 격리 입력에서 'Main candidate unestimable: 식음료/공간', 보고서 생성 안 됨.
현재 수치 영향: 현재 144개 결과에는 이 상황이 없어 기존 수치를 무효화할 이유는 없다.
권고: summary와 표시에 status·candidate=null·fallback을 보존하고 다른 그룹을 계속 보고한다. fallback은 CRITIC 추정 결과와 명확히 구분한다. 핵심 함수 테스트만으로 끝내지 말고 실행 도구 전체의 상수·완전상관·표본부족 통합 테스트를 추가한다.

F2. 규칙 문서를 바꿔도 실행이 그 의미를 따르는지 보장하지 못함
위치: tools-stage3/calculate_stage3.py 55~61행, 140~141행.
재현: 주 정규화 이름을 존재하지 않는 unsupported_model_for_audit로 바꾼 격리 규칙을 넣었는데도 실행이 성공해 기존 고정척도 결과를 생성했다.
현재 수치 영향: 현재 승인된 규칙과 코드의 설정은 맞아서 현재 계산 오류는 아니다. 팀이 산식·입력·정규화 규칙을 개정한 이후의 오해 가능성이 문제다.
권고: 규칙의 schema/method 및 지원하는 핵심 옵션을 명시적으로 검사한다. 지원하지 않는 값이면 계산 전에 중단한다. 가능한 항목은 규칙에서 실제로 읽도록 하고 하드코딩이 필요한 부분은 지원 버전과 대조한다.
관련 보완: 승인 원본 manifest와 재배치 manifest 연결은 별도 validation JSON에서 검증되어 있다. 두 manifest 해시가 다른 것은 경로·구조 변경 때문이며 현재 데이터 불일치가 아니다. 이 검증도 실행 도구 진입점에 포함한다.

F3. '기존 실제 적용 비중'의 비교 기준 표현이 혼동을 줌
위치: tools-stage3/calculate_stage3.py 223행.
현재 비교표의 비용 기존값 50/30/20(공연문화 40/30/30)은 예산 300만 원 시나리오에서의 기존 프리셋이다.
동결된 실제 기본 결과는 budget=null이므로 임대료 부담이 빠져 일반 업종의 유효 비용 비중은 —/60/40, 공연문화는 —/50/50이다.
계산은 같은 예산 시나리오를 비교하는 것으로 타당하지만, 이를 현재 기본 상태의 실제 비중으로 읽으면 잘못이다.
권고: '300만 원 시나리오에서 기존 프리셋과 후보 비교'로 표제를 수정하고 '현재 무예산 기본 상태'를 별도 행/표로 둔다. 일반 결측이 있는 매물은 유효 비중이 다시 달라짐을 명시한다.

F4. 범용 기법과 파일럿 코드의 범용성이 다름
위치: tools-stage3/calculate_stage3.py 182~196행.
현재 도구는 2,669건·32개 주 그룹·기존 그룹별 완전 관측 수를 검증식에 고정했다.
재현: 좌표를 1건 제외하고 규칙의 기준 수를 2,668건으로 일치시킨 격리 새 입력에서도 하드코딩한 기준 수와 완전 관측 수 검사에서 중단했다.
현재 수치 영향: 현재 스냅샷에 대한 회귀 검증으로는 의미가 있다. 현행 데이터를 보호하는 검사 자체가 잘못된 것은 아니다. 다만 새 업종 수·새 데이터에 그대로 재사용하는 범용 도구는 아직 아니다.
권고: 현재 스냅샷 무결성 검증, 버전별 회귀 기대값, 일반 알고리즘의 구조 검증을 나눈다. 일반 검증에서는 업종 수×그룹 수와 실제 결측 집합으로 기대값을 산출한다.

3. 오류와 구분해서 판단해야 할 방법론

M1. 주 후보가 원문 전체 절차와 동일한 것은 아님
주 후보는 기존 점수를 100으로 나누는 고정척도 유지형이고, 원문은 표본 min-max 정규화 후 정보량을 계산한다. 이 차이는 기존 문서에도 공개되어 있으며 숨겨진 산술 버그는 아니다.
하지만 영향은 작지 않다. 사무업무 공간의 면적 비중은 고정척도 43.9669%, min-max 후보 34.0625%로 9.9044%p 다르다. 비용의 임대료 부담도 21.5445%와 30.6426%로 9.0981%p 다르다.
따라서 'CRITIC을 사용했으니 이 비율이 객관적 정답'이라고 확정할 수 없다. 정규화 선택도 설계 판단이다.
권고: 두 후보와 동일 비중을 함께 비교하되 한 후보를 정답으로 승격하지 않는다. 원문 전체 파이프라인 재현을 목표로 바꾸면 정규화한 점수의 최종 집계까지 별도로 정의한다. 현재 보조 min-max는 가중치 산출 전처리 비교이며 원문 전체 추천 결과를 재현한 것은 아니다.

M2. 인자가 2개면 상관항의 이점이 없어짐
두 인자의 정보량 C1=sd1*(1-r), C2=sd2*(1-r)이므로 r<1이면 비중은 sd1:sd2다. 계산 오류가 아니다.
주 후보 32개 그룹 중 9개(8개 업종 적합 그룹 + 공연문화 공간)에 해당한다. 전체 조건별 레코드에서는 34개가 two_factor_sd_ratio 상태다.
권고: 이 경우 '2인자 표준편차 비율'로 표시하고 기존·동일 비중과 같이 평가한다. 무조건 다른 무라벨 알고리즘으로 바꾼다고 임차인 선호가 생기는 것은 아니다.

M3. 관리비 미기재와 검증 범위
관리비 미기재는 원본 전체 1,657/2,717건, 기준 집합 1,626/2,669건이다. 현재 0 대치는 기존 엔진을 재현하는 규칙일 뿐 실제 0원임을 확인한 값이 아니다.
300만 원 주 비용 표본 2,235건 중 관리비 기재 표본은 825건이므로, 나머지 1,410건은 이 대치 규칙의 영향을 받는다. 실제 총비용이 예산 이내인지까지 검증했다고 말하면 안 된다.
권고: 이미 생성한 관리비 기재 표본 후보와 0 대치 후보를 분리해 비교하고, 표본 차이도 함께 설명한다. 관리비를 모르는 상태와 실제 0원을 구분하는 정보 표시는 후속 적용 과제로 둔다.

M4. 수치 검증은 추천 품질 검증과 다름
1단계의 총점 재구성 오차 약 0.069점은 집계 구현의 내부 일관성 증거다. 개별 산식의 학술적 타당성, 매물 정보의 진실성, 임차인 만족도를 입증하지 않는다.
3단계 단위 테스트와 독립 언어 검산도 계산 구현의 증거다. 가중치 값이 실제 중요도와 같다는 증거가 아니다.
순위·재표집이 안정적으로 나와도 실제로 좋은 매물을 추천한다는 결론은 별도다. 현재는 선호/결과 라벨이 없는 환경이므로 이 검증 한계를 유지해야 한다.

4. 권하는 해결 순서
1) F1 산출 불가 처리, F2 설정/버전 검사, F3 비교표 표현을 먼저 수정한다. F4는 현재 스냅샷 전용과 새 버전 재사용 모드를 분리해 정리한다.
2) 수정 후 현재 동결 입력으로 3단계를 재실행한다. 표시·상태 처리만 바꾼다면 현재 성공한 비중 수치가 그대로 나와야 한다.
3) 위 격리 사례 3개를 통합 검증으로 고정한다: 상수 그룹은 산출 불가 보고와 다른 그룹 완료, 미지원 설정은 조기 중단, 새 표본 수는 명시한 버전/모드 규칙에 맞게 처리.
4) 그 뒤 기존·동일·고정척도·min-max 후보를 같은 예산/후보 집합에서 비교하는 4단계를 진행한다. 추천 편입·탈락과 공통 대상의 순위 변화를 분리한다.
5) 4단계 결과를 사용자와 검토한 후 적용 여부를 정한다. 자동으로 기존 프리셋이나 화면에 반영하지 않는다.

5. 보존과 현재 상태
이번에는 기존 1~3단계 파일을 고치지 않고 이 재검토 보고서와 증거만 새로 저장했다. 수정은 아직 적용하지 않았다.
4단계 순위·부트스트랩 분석은 진행하지 않았다. 앞서 4단계 시작 안내 뒤에는 도구 목록 확인만 있었고, 계산 프로세스는 시작되지 않았다.
현재 3단계 수치를 폐기할 필요는 없지만 '실험 후보' 지위를 유지해야 한다.
