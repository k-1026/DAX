# 09.스코어링 — 외부 데이터 인자 (v1)

`data/scripts/external_factors.py` 실행 결과입니다. 다시 계산하려면 저장소 루트에서:

```
py -I data/scripts/sgis_oa.py            # SGIS 집계구 데이터 수집 (처음 한 번, 원본은 raw/에 캐시)
py -I data/scripts/external_factors.py
```

## 파일

| 파일 | 내용 |
|---|---|
| `외부인자_v1.csv` | 매물별 행정동, 행정동 판정, 업종별 배후 수요 점수(`배후수요_`, 집계구 방식), 반경 내 인구·종사자 합(`반경…_300m/500m`), 옛 행정동 방식 점수(`배후수요동_`, 비교용), 상권 활성도 점수, 반경 내 전체 상가 수, 업종별 주변 동종 상가 수 |
| `행정동_배후수요_v1.csv` | 대구 행정동 150개의 인구·연령대 인구, 면적, 인구밀도, 대구 내 백분위 (옛 행정동 방식 참고용) |
| `외부인자_v1_meta.json` | 출처, 기준일, 반경, 업종 매핑 규칙, 매칭률, 상권 활성도 기준값, 배후 수요 방식·지표, 집계구 배분 검산값 |

## 계산 규칙

- **행정동 판정:** 매물 좌표가 행정동 경계 안에 있는지로 판정합니다. 반경 20m 안 상가 3곳 이상의 70% 이상이 다른 행정동(상가정보 주소 기준)을 가리키면 그쪽으로 보정합니다(`주변상가로보정`). 매물의 구·법정동과 맞지 않으면 플래그를 붙입니다.
- **상권 활성도 (0~100):** 업종 기본 반경(300m 또는 500m) 안 전체 상가 수의, 좌표가 있는 대구 매물 2,669건 중 백분위입니다.
- **배후 수요 (0~100), 집계구 방식 (2026-11-11 채택):** 매물 반경(업종 기본 반경) 안 인구·종사자 수의 합을, 좌표가 있는 대구 매물 중 백분위로 바꾼 값입니다.
  1. **거주인구 배분:** 행정동 주민등록 인구(2026-10, 1세 단위)를 SGIS 집계구(2024) 10세 단위 인구 비율로 동 안 집계구에 나눕니다. 배분 합계 2,345,185명 = 주민등록 대구 합계.
  2. **직장인구:** SGIS 집계구 종사자 수(2024)를 그대로 씁니다. 합계 992,260명.
  3. **반경 합계:** 집계구마다 50m 간격 표본점(총 604,160개)에 값을 나눠 담고, 매물 반경 안 표본점을 더합니다.
  4. **업종별 지표:**

     | 업종 | 반경 | 지표 |
     |---|---|---|
     | 식음료 | 300m | 20~59세 50% + 종사자 50% |
     | 소매 | 300m | 전체 인구 |
     | 뷰티 | 300m | 20~49세 |
     | 공연문화 | 300m | 20~39세 |
     | 의료 | 300m | 전체 인구 50% + 65세 이상 50% |
     | 교육 | 500m | 6~18세 |
     | 운동시설 | 500m | 20~49세 |
     | 사무업무 | 500m | 종사자 |

  - **채택 이유:** 행정동 방식은 같은 동 매물이 모두 같은 점수였습니다. 집계구 방식에서는 같은 동 안에서도 업종별 중앙값 38~64점 차이가 나고, 사무업무 배후 수요(종사자)도 계산됩니다. 두 방식의 순위 상관은 0.37~0.50입니다.
  - 옛 행정동 방식 값은 `배후수요동_` 컬럼에 비교용으로 남겨 둡니다.
- **주변 동종 상가 수:** 점수에 넣지 않는 정보용 값입니다. 업종 매핑은 meta.json의 `상가_업종매핑`을 보세요.

## 한계

- **집계구 연도 차이:** 동 안 배분 비율과 종사자 수는 2024년 SGIS 값입니다. 거주인구 총량만 2026년 주민등록입니다.
- **연령 구간 근사:** SGIS는 10세 단위만 제공해서 6~18세는 0~9세의 40% + 10~19세의 90%, 65세 이상은 60~69세의 50% + 70세 이상으로 근사합니다.
- **종사자에 제조업 포함:** 산업단지(예: 성서산단)는 사무업무·식음료 배후 수요가 높게 나올 수 있습니다.
- **소수 인원 비공개:** SGIS가 N/A로 주는 값(소수 인원 보호)은 0으로 처리합니다.
- **집계구 안은 균등 분포로 가정합니다.** 공원·산이 큰 집계구는 실제보다 넓게 퍼집니다.
- **주민등록 출장소:** 달성군 논공읍공단출장소·다사읍서재출장소 행은 경계 파일에 따로 없어서 각각 논공읍·다사읍에 합칩니다.
- **구지읍:** 2026-09-30 면→읍 승격으로 코드가 바뀌어, SGIS 2024년 옛 코드(22510360)에 이름으로 연결합니다.
- 상가정보에는 공연장·연습실·전시 업종이 없어서 공연문화 동종 수가 실제보다 적게 잡힙니다.
- 좌표가 없는 매물 48건은 계산하지 않았습니다(빈값).

## 건물 용도 적합성 (`건물용도_v1.csv`)

`py -I data/scripts/building_use.py` 실행 결과입니다. 키는 `data/.env`에서 읽습니다(git 제외).

1. **필지 매칭:** 매물 좌표가 들어 있는 필지(브이월드 연속지적도)를 찾습니다. 그 필지에 건축물대장이 있으면 `점포함`으로 판정합니다. 없으면 반경 30m 안에서 가장 가까운 건물 있는 필지를 쓰고 `근사`(거리 기록)로 판정합니다.
2. **건물 선택:** 한 필지에 건물이 여러 동이면 사용승인일 → 지상 층수 → 건물명 순서로 대조해 고릅니다.
3. **매칭 검증:** 매물 CSV의 사용승인일·전체층·건물명을 건축물대장과 대조합니다. 하나 이상 일치하고 불일치가 없으면 `높음`, 일치가 없고 불일치가 있으면 `확인필요`입니다.
4. **용도:** 매물 층과 같은 층의 층별개요 용도를 씁니다. 같은 층에 용도가 여러 개면 매물 면적과 가장 가까운 것을 고릅니다. 층을 특정할 수 없으면 건물 주용도를 씁니다.
5. **등급**(건축법 시행령 별표1 단순화):
   - A(100점): 등록 용도 그대로 가능
   - B(80점): 같은 근린생활시설군 안에서 기재변경 수준이거나, 업종 일부만 가능
   - C(40점): 다른 시설군이라 용도변경 필요
   - D(30점): 주거용도

**주의:** 면적 기준은 법령상 "같은 건물에서 해당 용도로 쓰는 바닥면적 합계"인데, 여기서는 매물 전용면적으로 근사했습니다. 실제 입점 가능 여부는 관할 구청 건축과에서 확인해야 합니다. 브이월드 결과는 저장 허용 조건을 확인하기 전이라 필지 도형은 저장하지 않고 PNU만 캐시합니다.

## 점수 엔진 (`점수_v1.csv`)

`py -I data/scripts/scoring_engine.py [--budget 300] [--want 80]` 실행 결과입니다. 위 두 스크립트의 결과를 읽어서 업종 8개의 총점을 계산합니다.

- **총점** = Σ(그룹 가중치 × 그룹 점수) ÷ (데이터가 있는 그룹의 가중치 합). 그룹 점수도 같은 방식으로, 데이터가 없는 인자는 빼고 비중을 재분배합니다.
- **반영률** = 100점 배점 중 실제 값이 들어간 배점의 합입니다. **60 미만이면 추천 대상에서 제외**합니다(`추천대상_업종` = False). 그룹 하나가 통째로 비면(예: 좌표 없음 → 입지 전체) 남은 그룹이 과대 반영되어 점수가 부풀기 때문입니다.
- **예산(`--budget`)이 없으면** 임대료 부담 인자를 뺍니다. **희망 면적(`--want`)이 없으면** 업종 중앙값을 목표 면적으로 씁니다.
- **건물 용도:** 매칭 신뢰도가 `확인필요`인 매물은 이 인자를 쓰지 않습니다.
- **설정 파일:** 가중치와 기준값은 `점수_v1_config.json`에 저장합니다. 화면과 피드백 스냅샷은 이 파일을 기준으로 씁니다.
- **검사 파일:** `점수_v1_검사.json`에 업종별 점수 분포, 반영률, 업종 간 상위 10개 겹침(대구 전체와 구별)을 기록합니다.

## 스코어링 보드 데모와 평가 저장

`py -I data/scripts/build_demo.py`가 점수 결과를 `data/scripts/demo_template.html`에 넣어 두 파일을 만듭니다.

| 파일 | 쓰는 곳 | good/bad 평가 저장 |
|---|---|---|
| `발표용 데모파일/v1.대구_공실추천_데모.html` | 내 컴퓨터에서 열기 (브이월드 배경지도) | 이 브라우저(localStorage). [평가 내보내기 (JSON)]로 파일 저장 → `data/10.피드백/` |
| `data/scripts/out/demo_artifact.html` | claude.ai 게시본 (외부 지도 타일이 막혀 법정동 경계를 배경으로 그림) | artifact 공유 DB `feedback/<평가자 id>/items/<매물번호>_<업종 번호>` |

- **화면 점수 = 엔진 점수:** 화면은 엔진의 인자 점수를 읽고, 사용자 입력(임대료 상한, 희망 면적, 그룹 가중치)만 다시 계산합니다. 2026-11-11 검사에서 8개 업종 × 2,717건 모두 차이 0.07점 이하(소수 반올림), 추천 대상 판정은 완전히 일치했습니다.
- **평가 1건에 남는 것:** 매물번호, 업종, good/bad, bad 사유, 동종 상가 영향 응답, 총점·반영률·추천 대상 여부, 그룹 가중치·그룹 점수·인자 점수, 건물 용도 등급·매칭 신뢰도, 입력 조건, 정렬, 목록 순위, 주변 동종 상가 수·지도 열람 여부, 기준값 버전, 데이터 기준일, 평가 시각.
- **같은 매물·같은 업종을 다시 평가하면** 최신 평가로 덮어씁니다.
- **DB 권한:** 평가자는 자기 평가만 읽고 씁니다(공유 권한 Contributor 이상 필요). 소유자·편집자는 화면의 [팀 전체]로 업종별 good 비율을 봅니다. Claude는 `ArtifactData`로 전체를 읽어 모델 보정에 씁니다.
