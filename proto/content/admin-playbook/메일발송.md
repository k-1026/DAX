# 메일 발송 — 다음에 할 일 제안 규칙

> 이 파일의 문구와 기준 숫자를 고치면 관리자 화면 "메일 발송"의 제안이 바뀝니다(서비스에 반영하려면 배포가 필요해요).
> 쓸 수 있는 이름: 발송_24시간(성공+실패), 성공률_24시간(%; 발송이 없으면 100), 성공률_기준(설정값에서 읽어 옴), 실패_24시간, 이번달_발송, 이번달_실패,
> 지연_미룸_수(예정 시각을 1시간 넘긴 미룬 메일), 대기_수, 수신거부_7일, 수신거부_전주, 수신거부_배수(전주가 0이면 1로 계산), 수신_동의_인원, 발송_7일

## 기준 숫자
- 수신거부_최소: 3
- 수신거부_배수_기준: 2
- 동의_최소_인원: 5

## 상황: 최근 24시간 메일 성공률이 기준보다 낮아요
- 수준: 지금 확인
- 조건: 발송_24시간 >= 1 그리고 성공률_24시간 < 성공률_기준
- 해석: 최근 24시간 성공률이 {성공률_24시간}%예요(기준 {성공률_기준}%). 실패가 {실패_24시간}통이에요.
- 할 일: '메일 발송' 화면의 최근 발송 기록에서 실패 이유가 같은 것인지 확인하세요. 메일 서비스 설정(발신 주소, 키)이나 받는 주소 문제일 수 있어요.

## 상황: 미룬 메일이 예정 시각을 넘겼어요
- 수준: 지금 확인
- 조건: 지연_미룸_수 >= 1
- 해석: 아침으로 미룬 메일 {지연_미룸_수}통이 예정 시각을 1시간 넘게 지나도 나가지 않았어요.
- 할 일: 발송 예약 호출이 계속 오고 있는지 확인해 주세요. 발송이 멈췄다면 사용자는 추천 메일을 못 받고 있어요.

## 상황: 이번 달 실패한 메일이 있어요
- 수준: 곧 점검
- 조건: 이번달_실패 >= 1
- 해석: 이번 달 실패한 메일이 {이번달_실패}통이에요(발송 성공 {이번달_발송}통).
- 할 일: '메일 발송' 화면의 실패 이유에서 같은 이유가 반복되는지 보고, 반복되면 원인을 먼저 고쳐 주세요.

## 상황: 수신 거부가 갑자기 늘었어요
- 수준: 곧 점검
- 조건: 수신거부_7일 >= 수신거부_최소 그리고 수신거부_배수 >= 수신거부_배수_기준
- 해석: 최근 7일 수신 거부가 {수신거부_7일}명이에요(전주 {수신거부_전주}명).
- 할 일: 최근 보낸 메일의 제목·내용·빈도를 살펴보세요. 광고성 메일에 (광고) 표기와 수신 거부 링크가 잘 보이는지도 확인해 주세요.

## 상황: 동의한 회원이 있는데 최근 발송이 없어요
- 수준: 참고
- 조건: 수신_동의_인원 >= 동의_최소_인원 그리고 발송_7일 == 0
- 해석: 수신 동의 중인 회원이 {수신_동의_인원}명인데 최근 7일 발송이 0통이에요.
- 할 일: 회원들이 선호 조건을 저장했는지, 갱신 메일 단계가 동작하는지 확인해 보세요. 매물 갱신이 멈춰 있어서일 수도 있어요.

## 상황: 보내기를 기다리는 메일이 있어요
- 수준: 참고
- 조건: 대기_수 >= 1 그리고 지연_미룸_수 == 0
- 해석: 보내기를 기다리는 메일이 {대기_수}통이에요.
- 할 일: 밤 9시~아침 8시에 모인 메일은 아침에 나가요. 아침이 지나도 남아 있으면 다시 확인해 주세요.

## 기본: 메일 발송은 정상이에요
- 해석: 성공률 기준을 지키고 있고 미룬 메일 지연이 없어요.
- 할 일: 그대로 지켜보세요. 이상이 생기면 위쪽에 알림이 떠요.
