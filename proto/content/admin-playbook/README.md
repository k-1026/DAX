# 관리자 "다음에 할 일 제안" 규칙 파일

관리자 화면 7곳(AI 사용량, 매물 갱신, 에이전트 실행, 메일 발송, 품질·개선 제안, 가중치 보정안, 사용자 현황)의 "다음에 할 일 제안" 박스는 이 폴더의 md 파일로 만들어요.
코드가 숫자를 계산하고, md는 "어떤 상황이면 무슨 말을 할지"를 정해요. AI 비용은 들지 않아요.

| 화면 | 파일 |
|---|---|
| AI 사용량 | AI사용량.md |
| 매물 갱신 | 매물갱신.md |
| 에이전트 실행 | 에이전트.md |
| 메일 발송 | 메일발송.md |
| 품질·개선 제안 | 품질개선.md |
| 가중치 보정안 | 가중치.md |
| 사용자 현황 | 사용자현황.md |

## 한 상황을 쓰는 법
```
## 상황: 제목(박스에 그대로 보여요)
- 수준: 지금 확인   (지금 확인 / 곧 점검 / 참고 중 하나)
- 조건: 오늘_사용 >= 10 그리고 급증_배수 >= 급증_배수_기준
- 해석: 오늘 {오늘_사용}회로 평소의 {급증_배수}배예요.
- 할 일: 원인을 확인해 주세요.
```
- **조건**은 숫자 이름과 `>=  <=  >  <  ==  !=`, `그리고`, `또는`, 괄호, `+ - * /`로 써요. 쓸 수 있는 이름은 각 파일 맨 위 설명에 있어요.
- **해석·할 일**의 `{이름}` 자리에 숫자나 글자가 들어가요.
- **기준 숫자** 구역(`## 기준 숫자`)에 `- 이름: 숫자`로 적어 두고 조건에서 이름으로 써요. 숫자를 바꾸려면 여기만 고치면 돼요.
- 아무 상황도 맞지 않으면 `## 기본: 제목` 구역의 문구를 보여 줘요.
- 조건은 위 계산만 읽어요. 다른 코드를 넣어도 실행되지 않고 오류로만 알려져요.

## 고친 뒤
1. 터미널에서 `npm test`를 돌려 문법 오류가 없는지 확인해요(`tests/playbook.test.mjs`).
2. 서비스에 반영하려면 배포가 필요해요.
3. 규칙에 잘못된 곳이 있으면 화면 박스 아래에 "규칙 파일에 고칠 곳이 N군데 있어요"가 나오고, 나머지 규칙은 계속 동작해요.

## 나중에 실제 AI로 바꿀 때
같은 md와 코드가 계산한 숫자(신호)를 AI에게 지침으로 주면 돼요(`lib/admin/playbook-files.ts`의 `adviseScreen`만 바꿔 끼우면 화면은 그대로예요).
