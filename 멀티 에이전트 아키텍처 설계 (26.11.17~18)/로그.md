# 대화 로그 · 멀티 에이전트 아키텍처 설계 (26.11.17~18)

사용자와 Claude Code가 이 폴더의 코드를 함께 만든 과정을 순서대로 정리한 기록이다.
요청은 사용자의 말을 요약했고, 결과는 실제로 실행해서 확인한 내용이다.
API 키 등 비밀 값은 적지 않았다.

## 진행 원칙 (사용자가 정한 규칙)

- 순수 Python과 공식 SDK(`google-genai`)만 쓴다. LangChain·LangGraph 같은 프레임워크는 쓰지 않는다.
- LLM은 Google Gemini. API 키와 모델 이름은 `.env`에서 읽는다.
- 코드 작성 전에는 공식 SDK 문서에서 최신 사용법을 확인하고, 기억에 의존하지 않는다.
- 한 단계씩 진행하고, 단계마다 직접 실행해 출력을 확인한 뒤 다음 단계로 간다.
- 사용자가 지시한 단계만 진행하고, 지시 전에는 코드를 작성하지 않는다. 요청하지 않은 기능은 넣지 않는다.
- RAG 실습의 색인 대상은 `DOCS` 폴더뿐이다. 다른 폴더의 문서는 색인하지 않는다.

## 1일차 · 2026-11-17 — 멀티 에이전트

### 1. 구조 설계
- **요청:** 사용자 입력을 오케스트레이터가 받아 서브에이전트에게 자율적으로 일을 맡기고, 결과를 종합해 알려 주는 구조를 설명해 달라.
- **결과:** 서브에이전트를 오케스트레이터의 "도구(FunctionDeclaration)"로 등록하는 구조로 정했다. 오케스트레이터는 함수 호출 루프를 돌며, 도구 호출이 없을 때의 응답을 최종 답변으로 쓴다.
- **결정:** 서브에이전트는 리서치 / 작성 / 검토 3개. 모두 각자 Gemini를 호출한다.
- **결정:** 사용자 입력은 터미널이 아니라 GPT 같은 웹 채팅창에서 받는다.

### 2. 1단계 · 환경 준비
- `requirements.txt`, `.env`(GEMINI_API_KEY, MODEL_NAME), `config.py` 작성.
- 사용자가 `config.py`의 `os.getenv()` 안에 값을 직접 넣은 것을 되돌리고, 값은 `.env`에 넣도록 안내했다.
- `.env`의 API 키가 비어 있어 첫 테스트는 실패했고, 키를 넣은 뒤 `gemini-3.5-flash-lite` 호출에 성공했다.

### 3. 2단계 · 서브에이전트
- `subagents.py`에 `SubAgent` 클래스와 `research_agent`, `writer_agent`, `review_agent`를 만들었다.
- 사용자 요청으로 3개를 먼저 다 만들고 각각 단독 실행해 결과를 확인했다.

### 4. 3단계 · 오케스트레이터
- `orchestrator.py`: 서브에이전트 3개를 도구로 선언하고, 자동 함수 호출은 끄고 루프를 직접 작성했다.
- **문제:** 공식 문서 예시대로 함수 결과를 `role="tool"`로 보내자 `400 Role 'tool' is not supported` 오류가 났다.
- **해결:** 설치된 SDK 내부 코드도 `role="user"`로 보내는 것을 확인하고 그렇게 바꿨다.
- **결과:** 리서치 → 작성 → 검토를 차례로 호출하고 종합 답변을 완성했다.

### 5. 웹 채팅 UI
- 처음에는 Python 표준 `http.server`로 계획했지만, 사용자 요청으로 FastAPI로 바꿨다.
- `server.py`(GET /, POST /chat), `static/index.html`(채팅창) 작성. 브라우저에서 질문과 답변 표시를 확인했다.

### 6. WBS 간트차트
- 이 프로젝트를 5인 팀이 6주(30작업일) 동안 진행한다고 가정한 WBS를 `wbs_gantt.html`로 만들었다.
- 8단계, 작업 24개, 마일스톤 4개.

### 7. 에이전트 작동 시각화
- **요청:** 첫 화면은 채팅창만 보이고, 입력하면 좌우로 나뉘어 오른쪽에 조직도가 나오게 해 달라. 작업 중인 에이전트는 오로라로 일렁이고, 작업 로그가 쌓이게 해 달라.
- `orchestrator.run_stream()`으로 진행 이벤트를 만들고, FastAPI SSE(`POST /chat/stream`)로 실시간 전달했다.
- 브라우저에서 화면 분할, 순서대로 이동하는 오로라, 로그 누적을 확인했다.

## 2일차 · 2026-11-18 — RAG → Agentic RAG → Multi Agentic RAG

### 8. RAG 자료 준비
- k-1026/DAX 저장소 `지해나` 브랜치의 `공실 서브에이전트` 폴더를 md 10개로 `DOCS`에 저장했다.
- 9개는 원본 md에 html 내용이 모두 들어 있어서 그대로 복사했다. `서브에이전트 구성도.md`는 요약본이라 html에서 새로 변환했다.
- **파일 분석:** md 10개, 21,118자, 이미지 없음.
- **색인 제외 제안:** `서브에이전트 구성도.md`. 00~05와 내용이 겹치고, 상세 명세와 다른 내용이 있다(에이전트 5개 vs 7개, ⑥이 기준값을 직접 조정한다 vs 제안만 한다). 제외하면 9개, 18,800자.

### 9. 실습 질문 확정 (`질문.md`)
1. 문서 하나에 답: 교육 업종 반경 → 500m (03_입지상권분석)
2. 두 문서 비교: 좌표 없는 매물을 ②와 ③이 어떻게 처리하나 (02, 03)
3. 문서에 답이 없음: 달서구 평균 권리금
- 3-3. 문서에는 없지만 웹으로 알 수 있음: 토지이음 운영 기관 → 국토교통부

### 10. RAG (`rag.py`)
- 벡터 DB와 RAG 프레임워크 없이 numpy로 만들었다.
- 조각은 500자, 겹침은 100자이고, 표 행이 잘리지 않도록 줄 단위로 나눈다. 출처는 `DOCS/파일명` 형태로 보관한다.
- 임베딩은 `gemini-embedding-2`(768차원). 문서 조각에는 `title: … | text: …`, 질문에는 `task: search result | query: …`를 앞에 붙인다.
- 49개 조각, 질문 4개 모두 기대한 답이 나왔다.
- 조각 크기와 겹침 측정표, `chunk_preview.txt`(조각 전문 미리보기)를 만들었다.
- **임베딩 캐시** `rag_index.npz`: 조각이나 설정이 바뀌면 자동으로 다시 만든다. 캐시가 있으면 0.00초에 불러온다.
- **문제:** 무료 등급의 임베딩 한도(분당 100건)에 걸려 429 오류가 났다.
- **채팅창 연결:** RAG / 멀티 에이전트 모드 전환을 넣었고, RAG 답변 아래에 근거 조각을 보여 준다.

### 11. Agentic RAG
- 기존 `agent_loop.py`를 찾지 못해서 사용자 선택으로 새로 만들었다. `run_agent`는 범용 함수 호출 루프이고, 이후 고치지 않는 파일이다.
- `tool.py`의 `search_docs` 도구는 조각 본문과 출처 파일명을 담은 문자열을 돌려준다.
- `agentic_rag.py`: 사용자가 준 시스템 프롬프트를 그대로 썼다(핵심 키워드로 다시 쓰기, 주제별 검색, 재검색, 최대 5회, 문장마다 출처, '문서에서 찾지못함'). 5회 제한은 코드로도 막았다.
- **결과:** 상식 질문(대한민국 수도)은 검색하지 않았고, 답이 없는 질문은 검색어를 바꿔 다시 찾은 뒤 '문서에서 찾지못함'으로 답했다.
- **채팅창:** 첫 화면에서 모드를 고르게 했고(RAG / Agentic RAG / 멀티 에이전트), 검색 과정을 표시한다.
- **문제:** 사용자가 HTML 파일을 직접 열어 `Failed to parse URL from /rag` 오류가 났다. `http://localhost:8000`으로 열도록 안내했다.

### 12. Multi Agentic RAG
- `orchestrator.py`와 `agent_loop.py`는 고치지 않고, `multi_agentic_rag.py`에서 `run_agent`를 재사용했다.
- **에이전트 정의:** `agent/_template.yaml`(공용 템플릿과 보고 양식), `doc_searcher.yaml`(search_docs), `web_searcher.yaml`(web_search), `data_analyst.yaml`(query_table).
- **표:** `DOCS/규칙_수치표.csv`. 문서에 적힌 수치 30행을 출처와 함께 담았다.
- **오케스트레이터 규칙:**
  - 세부사항은 docs에서, 외부 사실은 웹에서 찾는다.
  - 답마다 출처를 적고, 다른 출처로 메꾸지 않는다.
  - 질문을 다시 써서 지시한다.
  - web_searcher와 researcher 중 무엇을 먼저 쓸지 사용자에게 묻는다.
- **문제:** 오케스트레이터가 순서를 묻기 전에 web_searcher를 먼저 실행했다. 묻기 전에는 실행되지 않도록 코드로 막았다.
- **문제:** 이 API 키에 구글 검색 할당량이 없어 web_search가 429 오류를 냈다. SDK가 계속 재시도해 1분 넘게 멈추기도 했다. 재시도를 끄고 30초 제한을 두어 약 1초 만에 '웹 검색 실패'로 돌아오게 했다.

### 13. 모니터링 화면 확장
- 멀티 에이전트(리서치·작성·검토), Multi Agentic RAG(문서 검색·표 조회·웹 검색·리서처), Agentic RAG(에이전트 → search_docs 도구)가 각자 조직도, 오로라, 작업 로그를 보여 준다.
- 진행 이벤트는 `run_agent`에 원래 있던 `on_event`로 받았다.

### 14. GitHub 업로드
- k-1026/DAX `지해나` 브랜치에 `멀티 에이전트 아키텍처 설계 (26.11.17~18)` 폴더로 커밋하고 푸시했다.

## 남은 과제
- **web_search:** 구글 검색 할당량이 있는 API 키로 실제 검색 결과와 출처 URL 추출을 확인한다.
- **오케스트레이터 답변 형식:** 웹 검색 실패를 본문에 적고도 '찾지 못한 것' 항목에는 "없음"이라고 쓴 문제를 고친다.
- **채팅창 표시:** 답변의 마크다운(`**굵게**` 등)이 기호 그대로 보인다.

## 실행 방법

```bash
pip install -r requirements.txt
```

`.env` 파일을 만든다.

```
GEMINI_API_KEY=발급받은_키
MODEL_NAME=gemini-3.5-flash-lite
EMBEDDING_MODEL=gemini-embedding-2
```

```bash
python -m uvicorn server:app --port 8000
```

브라우저에서 http://localhost:8000 을 열고, 첫 화면에서 모드를 고른다.
