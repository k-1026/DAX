# 대구 임대매물 수집 프롬프트 (중구·서구·남구, 공실 명시 매물)

```
[목표]
대구 ㅇㅇ(구 명)의 네이버 부동산 임대 매물 중, 중개사가 "공실"이라고 명시한 매물만 수집하고, 같은 호실 중복을 제거한 뒤 CSV와 지도 HTML로 정리한다.

[수집 조건 - 네이버 부동산 (fin.land.naver.com) 지도 API]
- 거래유형: 월세(B2), 단기임대(B3)
- 매물유형: 상가(D02), 사무실(D01), 지식산업센터(E04)
- 요청 엔드포인트: POST /front-api/v1/article/boundedArticles
  - body: filter, boundingBox{left,right,top,bottom}, precision, userChannelType="PC", articlePagingRequest{size:30, articleSortType, lastInfo}
  - size는 30만 가능(100은 오류)
  - 페이지 간 lastInfo로 이어받기
- 구별 박스 (경계가 겹치므로 넉넉히 잡음)


[수집 방법]
1. 박스마다 정렬을 두 번 돈다: RANKING_DESC 한 번, PRICE_ASC 한 번.
   - 한 정렬만 쓰면 페이지마다 순서가 바뀌어 매물이 빠진다.
   - 두 결과를 articleNumber로 중복 제거하고, 응답의 totalCount와 맞는지 확인한다.
2. 요청 간격은 약 1초. 한 번에 길게 돌리지 말고 시간 단위로 나눠서 실행한다.
3. 구 구분은 박스가 아니라 응답의 address.division(행정구역) 값으로 한다.
   - 박스에는 다른 구 매물이 섞인다(예: 중구 박스에 수성구·북구 등 4,600여 건).
4. 박스 경계를 넘는 매물은 다른 박스 결과에서 가져와 합친 뒤 중복 제거한다.
   - 예: 원대동(서구)은 서구 박스 동쪽 경계 밖이라 중구 박스 결과에 있었다.

[공실 명시 기준]
- 응답의 landInfo.currentPurpose(현재용도) 값에 "공실" 또는 "빈점포"가 들어 있는 매물만 남긴다.
  - 예: "공실", "공실(빈점포)", "리모델링 후 공실", "공실 무권리"
- 다음은 제외한다: 영업 업종(일반음식점, 카페, 사무실 등), 신규입점, 현재용도 칸 비어 있음.
- 제외 목록은 따로 보관한다(사유 포함).

[중복 제거 기준]
- 같은 호실로 보는 조건: 좌표(경도·위도 소수점 5자리, 약 1m), 층, 전체층, 전용면적, 보증금, 월세가 모두 같음.
  - 좌표는 같은 건물 안에서도 소수점 7자리에서 조금씩 달라서 5자리로 맞춘다.
- 그중 하나만 남김: 확인일(articleConfirmDate)이 가장 최근인 것, 같으면 노출시작일이 최근인 것, 그래도 같으면 매물번호가 큰 것.
- 삭제된 매물번호는 남은 행의 "삭제된_매물번호" 열에 적고, 삭제 목록 CSV를 따로 만든다.

[층 표기]
- 숫자 층: "1층", "2층" ...
- 지하: "지하 1층", "지하 2층"
- 전체층: 같은 형식(예: "4층"), 원문 "전체층"은 그대로 둔다.

[출력 파일]
  - UTF-8 BOM, 열 구성: 매물번호, 유형, 세부유형, 건물명, 거래유형, 법정동, 층, 전체층, 전용면적(㎡), 공급면적(㎡), 보증금(만원), 월세(만원), 관리비(만원), 현재용도, 추천용도, 현재용도_공실명시, 사용승인일, 노출시작일, 확인일, 확인방식, 중개사무소, 특징, 합쳐진_매물수, 삭제된_매물번호, 경도, 위도, 링크
  - 링크: https://fin.land.naver.com/articles/{매물번호}
- 중복 삭제 목록: 중복제거_삭제목록.csv
  - Leaflet + 브이월드 배경지도(https://xdworld.vworld.kr/2d/Base/service/{z}/{x}/{y}.png)
  - 구별 색 구분, 구·유형·거래유형·층으로 필터, 목록 정렬·검색·100개씩 페이지
  - 공실 명시 매물만 표시(체크박스 없이)
  - 좌표 없는 매물은 목록에만 표시
- 저장 위치: 다운로드 폴더(C:\Users\Green\Downloads). 같은 이름이 있으면 덮어쓰고 이전 HTML은 삭제한다.

[검증 체크]
- 파일 안에서 매물번호 중복이 0인지
- 구 파일 사이에 같은 호실(동일 좌표·층·면적·가격)이 없는지
- 공실 명시 열이 모두 O인지
- 지도 HTML에서 카드 숫자(구별 합계)가 CSV 행 수와 맞는지

[진행 원칙]
- 구는 한 번에 하나씩: 순서대로 결과를 보고받고 다음 구로 간다.
- 문제가 생기면(매물 누락, 박스 경계 의심, 정렬 결과 불일치, 기준이 애매한 중복 등) 먼저 묻고 결정한다.
- 로그인이나 개인정보가 필요한 작업은 하지 않는다. 매물 열람 정보만 사용한다.
- 공실 여부는 중개사 기재 기준이며 실제 공실은 현장 확인이 필요하다는 점을 결과에 명시한다.
```
